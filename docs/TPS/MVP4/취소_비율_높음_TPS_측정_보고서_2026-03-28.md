# MVP4 취소 비율 높음 TPS 측정 보고서

작성 시각: 2026-03-28T12:38:55Z

## 1. 목적

`docs/MVP_4/TPS_측정_계획.md`의 4.6 시나리오 기준으로, 비체결 주문을 생성한 뒤 빠르게 취소하는 조건에서 취소 처리량과 지연 시간을 확인했다.

이번 측정의 목적은 다음과 같다.

1. 취소 완료 처리량(`cancel_completed_tps`)의 안정 구간을 확인한다.
2. `cancel delay`가 짧아질 때 주문 생성-취소 cycle 회전율이 어떻게 부하를 증가시키는지 확인한다.

## 2. 측정 조건

- 시나리오: `scripts/k6/scenarios/cancel-heavy.js`
- 심볼: `BTC`
- 가격 설정: `MIN_PRICE=1`, `MAX_PRICE=999999999999`
- VU: `10`, `20`, `30`, `40`
- 측정 window: `300s`
- 비교 변수: `CANCEL_DELAY_MIN_MS`, `CANCEL_DELAY_MAX_MS`

주의:

- 본 시나리오는 실행 중 비체결 주문을 생성한 뒤 짧은 지연 후 취소하는 방식이다.
- 별도 seed 없이도 취소 경로를 측정할 수 있지만, 이 결과는 "기존에 쌓인 대형 오더북 취소"보다 "생성 후 빠른 취소"에 더 가깝다.

## 4. 해석

### 4.1 `cancel delay = 100~500ms`

- `VU=10`, `20`, `40` 모두 안정적으로 동작했다.
- `VU=40`에서도 `cancel_completed_tps=131`, `end_to_end_cancel_latency_p95_ms=19.92ms`로 여유가 있었다.
- 이 조건에서는 VU 증가에 따라 cancel TPS가 거의 선형적으로 증가했다.

### 4.2 `cancel delay = 20~200ms`

- `VU=20`에서는 `cancel_completed_tps=174.72`, `end_to_end_cancel_latency_p95_ms=28.45ms`로 안정적이었다.
- 같은 짧은 delay에서 `VU=30`으로 올리면 즉시 과부하가 발생했다.
- `VU=30` 결과에서는 `engine_queue_depth: BTC=10000`, `queue_wait_latency_p95_ms=15.7s`, `queue_full_rollback_count>0`, `error_rate>0`가 관찰되었다.

### 4.3 핵심 해석

- 이 시나리오에서는 `cancel delay`를 줄이는 것이 강한 부하 레버로 작용했다.
- delay가 짧아질수록 각 VU가 더 빠르게 주문 생성-취소 cycle을 반복하게 되고, 그만큼 place/cancel 총 처리량이 증가했다.
- 현재 조건에서는 "오픈 주문 체류 시간 증가"보다 "요청 회전율 증가"가 더 직접적인 과부하 요인으로 관찰되었다.

## 5. 결론

이번 실험 기준 취소 비율 높음 시나리오의 결과는 다음과 같이 정리한다.

- 안정 처리량:
  - `delay=100~500ms` 조건에서 최소 `131 cancel TPS`
  - `delay=20~200ms` 조건에서 약 `175 cancel TPS`
- 과부하 구간:
  - `VU=30`, `delay=20~200ms`에서 queue saturation과 backpressure 발생

보고서용 결론 문장:

> 비체결 주문을 생성한 뒤 20~200ms 내에 취소하는 조건에서는 약 175 cancel TPS를 큐 적체 없이 안정 처리했다. 동일한 짧은 delay 조건에서 VU를 30으로 높이면 queue saturation과 backpressure가 발생해 과부하 구간에 진입했다. 반면 delay를 100~500ms로 늘린 조건에서는 VU 40에서도 약 131 cancel TPS를 안정적으로 처리했다.

## 6. 시사점

- 취소 시나리오의 병목은 단순 취소 API 자체보다 주문 생성-취소 cycle 회전율에 더 민감하게 반응했다.
- `cancel_completed_tps`와 `cancel_order_tps`가 안정 구간에서는 거의 동일하게 유지되어 취소 완료율이 매우 높았다.
- 이후 "기존 open order 대량 취소" 시나리오를 별도로 보고 싶다면 `book-seed.js` 또는 `place-no-fill.js`로 open order를 먼저 적재한 뒤 취소 전용 시나리오를 분리하는 것이 좋다.
