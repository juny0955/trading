# Trading Exchange Engine - MVP Phase 5 작업 티켓

## 0. 운영 규칙

- 상태: `Todo` -> `InProgress` -> `Done`
- 기본 우선순위: `P0 > P1 > P2`
- 선행조건이 있는 티켓은 선행 완료 후 착수

## 2. 상세 티켓

### MVP5-001 Outbox / symbols / symbol state 스키마 정의

- 설명: Phase 5의 전달 보장과 sequence 복구를 위한 DB 스키마를 정의한다.
- 완료조건:
  - `symbols` 테이블을 거래 가능 심볼 Source of Truth로 정의
  - 초기 심볼 메타 seed SQL 반영
  - `outbox_events` 테이블 정의
  - `symbol_states.last_event_sequence` 정의
  - `outbox_events.event_type = MATCHING_RESULT_BUNDLE` 기본 계약 반영
  - `status`, `next_retry_at`, `sequence`, cleanup 배치용 인덱스 반영
- 리스크:
  - sequence source of truth와 cleanup 정책이 섞이면 재시작 복구가 불안정해질 수 있음
  - 설정 파일 기반 심볼 목록과 DB 심볼 목록이 병행되면 SoT가 흔들릴 수 있음

### MVP5-002 `event_sequence` 발급 및 재시작 복구 경로 구현

- 설명: 심볼별 `event_sequence` 발급기와 서버 재시작 시 복구 경로를 구현한다.
- 완료조건:
  - 심볼별 단조 증가 `event_sequence` 발급
  - `accepted_seq`와 별개 경계로 분리
  - startup 시 `symbol_states.last_event_sequence`에서 복구
  - 엔진 런타임은 `symbols.status = ACTIVE` 심볼 집합을 기준으로 기동
  - public/private 이벤트가 동일 심볼 sequence 공유
- 리스크:
  - sequence 재개 시점이 틀리면 gap 오탐 또는 순서 역전 발생

### MVP5-003 `MATCHING_RESULT_BUNDLE` DTO 및 직렬화 계약 도입

- 설명: 엔진 커맨드 1건 결과를 Outbox bundle 1건으로 표현하는 DTO와 직렬화 계약을 도입한다.
- 완료조건:
  - bundle payload에 `symbol`, `sequence`, `trades`, `orderUpdates`, `orderbookDeltas` 포함
  - 하위 원소 DTO 구조 정의
  - `eventId`, `traceId`, `eventVersion` 등 메타 포함
  - public/private fan-out 가능한 형태로 유지
- 리스크:
  - payload가 과도하게 비대해지면 publish latency 증가 가능

### MVP5-004 `PriceLevelDelta` 계산 경로 구현

- 설명: orderbook 변경 사항을 `PriceLevelDelta`로 수집하는 계산 경로를 도입한다.
- 완료조건:
  - `PlaceCalculationResult`, `CancelCalculationResult` 모두에 delta 포함
  - `newTotalQty == 0`일 때 level 제거 의미 반영
  - replay / cancel / partial fill 경로 정합성 유지
- 리스크:
  - orderbook live 상태와 delta 계산이 어긋나면 client 복구가 실패할 수 있음

### MVP5-005 엔진 결과 반영 트랜잭션에 Outbox bundle 기록 추가

- 설명: 엔진 결과 영속 반영 트랜잭션 안에서 bundle event와 symbol sequence를 함께 저장한다.
- 완료조건:
  - `EngineResultPersistenceService`에서 outbox insert 수행
  - 동일 트랜잭션에서 `symbol_states.last_event_sequence` 갱신
  - orders / trades / balances 반영과 outbox 기록이 원자적으로 묶임
- 리스크:
  - bundle 생성 책임이 분산되면 transaction 경계가 모호해짐

### MVP5-006 Outbox publisher lease-claim / retry / reclaim 구현

- 설명: `PENDING + next_retry_at` lease 기반 publisher 경로를 구현한다.
- 완료조건:
  - 운영 환경에서 `SELECT ... FOR UPDATE SKIP LOCKED`
  - H2 테스트 fallback 전략 반영
  - 별도 `SENDING` status 없이 lease claim 동작
  - timeout reclaim / retry / maxAttempts / FAILED 처리 구현
- 리스크:
  - reclaim 정책이 느슨하면 중복 발행 과다, 빡빡하면 회수 지연 발생

### MVP5-007 Outbox bundle fan-out 및 all-or-nothing publish 구현

- 설명: 저장된 bundle event 1건을 topic별 메시지로 분해 전송한다.
- 완료조건:
  - `/topic/orderbook.{symbol}`, `/topic/trades.{symbol}`, `/user/queue/orders` fan-out 구현
  - fan-out 하위 메시지가 동일 `eventId`, `symbol`, `sequence` 공유
  - 하위 topic 중 하나라도 실패하면 bundle 전체 재시도
  - WebSocket 전송은 트랜잭션 외부에서 수행
- 리스크:
  - 부분 성공 허용 시 sequence 정합성이 깨질 수 있음

### MVP5-008 STOMP WebSocket gateway 및 account session 라우팅 구현

- 설명: STOMP endpoint와 account 기준 private session 라우팅을 구현한다.
- 완료조건:
  - `WS /ws-trading?accountId={accountId}` 연결 경로 반영
  - `/topic/orderbook.{symbol}`, `/topic/trades.{symbol}`, `/user/queue/orders` 지원
  - public topic 대상 심볼은 등록 심볼 기준으로 제한
  - 미등록 심볼은 public 구독 및 브로드캐스트 대상에서 제외
  - private 채널은 accountId 존재/유효성 검증 only 적용
  - account scope에 맞는 private 메시지 전달
- 리스크:
  - 세션-계정 매핑 누락 시 private 이벤트 누수 가능

### MVP5-009 orderbook snapshot + delta merge 계약 반영

- 설명: REST snapshot과 WebSocket delta를 합치는 클라이언트 계약을 서버 응답에 반영한다.
- 완료조건:
  - `GET /orderbook/{symbol}` 응답에 snapshot 시점 `sequence` 포함
  - 등록 심볼만 snapshot 조회를 허용하고, 미등록 심볼은 문서화된 정책대로 차단
  - snapshot source를 `OrderBookCache`로 고정
  - public delta merge 규칙 반영
  - private gap 판정은 `payload.symbol` 기준으로 정리
- 리스크:
  - snapshot / delta race condition 처리 미흡 시 재동기화 실패

### MVP5-010 heartbeat / reconnect / 느린 소비자 disconnect 구현

- 설명: WebSocket 연결 운영 정책을 구현한다.
- 완료조건:
  - STOMP heartbeat 기본값 반영
  - reconnect 시 버퍼 폐기 + snapshot 재조회 정책 반영
  - `send-buffer-size-limit`, `send-time-limit` 기준 느린 소비자 disconnect
  - 관련 메트릭 증가
- 리스크:
  - 느린 소비자 처리 미흡 시 publisher 또는 broker backlog 증가

### MVP5-011 `TradingProperties` 확장 및 운영 파라미터 외부화

- 설명: Outbox / WebSocket 관련 운영 파라미터를 `TradingProperties`로 외부화한다.
- 완료조건:
  - `outbox.pollingIntervalMs`
  - `outbox.batchSize`
  - `outbox.maxAttempts`
  - `outbox.retryBackoffMs`
  - `outbox.retentionDays`
  - `settlementAsset` 전역 설정 반영 (`KRW` 단일 고정)
  - `websocket` 관련 heartbeat / buffer / time limit 설정 반영
  - `trading.symbols` 설정 리스트 제거
- 리스크:
  - 설정 누락 시 운영 환경 튜닝이 어려움
  - 정산 자산 정책과 심볼 메타(`quote_asset`)의 책임이 혼동되면 다중 정산으로 오해될 수 있음

### MVP5-012 Outbox / WebSocket / sequence 메트릭 보강

- 설명: Phase 5 신규 운영 메트릭을 추가한다.
- 완료조건:
  - `outbox.pending.count`
  - `outbox.bundle.size`
  - `outbox.publish.time`
  - `outbox.retry.count`
  - `outbox.publish.lag`
  - `outbox.failed.count`
  - `ws.broadcast.time`
  - `ws.active.sessions`
  - `ws.slow.consumer.disconnect.count`
  - `symbol` tag는 등록 심볼 집합 기준으로만 기록
- 리스크:
  - 메트릭 이름/태그가 일관되지 않으면 대시보드 재사용이 어려움
  - 미등록 문자열이 `symbol` tag로 유입되면 고카디널리티 오염이 발생할 수 있음

### MVP5-013 FOK / IOC 자료구조 최적화 구현

- 설명: 선형 스캔 대신 O(log N) 자료구조 기반 가용 수량 계산으로 전환한다.
- 완료조건:
  - 펜윅 트리 또는 세그먼트 트리 적용
  - tick size 기반 인덱싱 고려
  - LIMIT insert/cancel 성능 저하 방어
  - FOK/IOC 조회 경로 최적화
- 리스크:
  - 조회는 빨라져도 update 경로가 느려지면 전체 TPS가 악화될 수 있음

### MVP5-014 replay / rebuild 시 집계 구조 복원 검증

- 설명: 재기동 후에도 최적화 자료구조와 sequence 상태가 일관되게 복원되는지 검증한다.
- 완료조건:
  - replay 후 orderbook depth/잔량 복구
  - 누적 수량 구조 복원
  - `symbol_states.last_event_sequence` 복원 확인
- 리스크:
  - startup recovery가 live 처리와 다른 경로를 타면 drift 발생 가능

### MVP5-015 Outbox / WebSocket / FOK 통합 테스트 및 성능 검증

- 설명: Phase 5 핵심 정합성과 성능 목표를 통합 테스트와 측정으로 고정한다.
- 완료조건:
  - 재시작 후 `PENDING` 재발행 검증
  - 중복 재전송 무해성 검증
  - snapshot + delta merge 검증
  - private `payload.symbol` 기준 gap recovery 검증
  - heartbeat / reconnect / 느린 소비자 disconnect 검증
  - `symbols` 미등록 심볼 주문 거부 검증
  - `symbols.status != ACTIVE` 심볼 신규 주문 차단 검증
  - 미등록 심볼 snapshot 조회 차단 검증
  - 미등록 심볼 WebSocket public 구독/브로드캐스트 제외 검증
  - LIMIT BUY / MARKET BUY hold 및 체결 정산이 전역 정산 자산(`KRW`) 기준으로 동작함을 검증
  - 1,000레벨 이상 시나리오 FOK p95 30% 이상 개선 검증
  - LIMIT insert/cancel p95 저하 10% 이내 검증
  - 동일 시나리오 3회 반복 중앙값 기록
- 리스크:
  - 통합 시나리오 누락 시 운영 문제를 사전에 못 잡을 수 있음

### MVP5-016 Phase 5 DoD 검증 및 문서 마감

- 리스크:
